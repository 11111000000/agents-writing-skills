# Как агенту писать текст в реальном времени

> [!info] Контекст
> Когда агент пишет длинный текст, он не может «вспомнить» все правила сразу. Нужен практический алгоритм, встроенный в skill или в system-prompt. Этот документ — такой алгоритм.

## Выбор режима правки

Перед работой определите, сколько вмешательства нужно тексту. **Хороший исходный текст можно оставить почти без изменений** — это нормальный результат, а не недоработка.

| Режим | Что делает | Когда |
|---|---|---|
| **proofread** | Опечатки, пунктуация, очевидный канцелярит. Структуру и голос не трогать | Исходник уже хорош |
| **light** | + убрать AI-клише, hedging, RLHF-реплики. Структуру и голос не трогать | Текст в целом живой, но с штампами |
| **style** | + burstiness, голос (по образцам автора или нейтрально), rupture — где уместно | Текст ровный, безликий |
| **deep** | Полная переработка по 3-pass архитектуре (Audit → Rewrite → Verify) | Текст типично «модельный» |

## Алгоритм «Pre-flight → Write → Audit»

### Pre-flight (до написания)
1. **Определите голос**: 2–3 образца текста автора или 2–3 характеристики, аудитория, цель. Нет образцов — нейтральный режим (сохранять регистр исходника).
2. **Соберите факты**: имена, числа, даты, ссылки. Составьте явный список: **что известно** / **что спросить у пользователя**. Выдумывать недостающее запрещено — без фактов либо спросите, либо пометьте , либо пишите без них.
3. **Сформулируйте «крючок»** (lead) — первые 1–2 предложения должны быть конкретными, если конкретика реально известна.

### Write (само написание)
1. **Первый черновик** — пишите «плохо», не думая о стиле. Просто закройте содержание.
2. **Перечитать абзац за абзацем** и применить «Show, don't tell»: заменить абстракции **реальными** числами и фактами — только из списка pre-flight.
3. **Перечитать ещё раз** и применить burstiness: чередовать длины предложений.
4. **Зачистить лексику** по спискам [[lexicon-ru|lexicon-ru]] / [[lexicon-en|lexicon-en]].
5. **Сломать симметрию** — добавить 1–2 предложения «не по формату», если это уместно жанру и голосу.

### Audit (финальная смысловая самопроверка)

Проект **не подчиняется детекторам**: «прогнать через детектор» рутинным шагом не является. Вместо этого — самопроверка по смыслу:

1. **Чек-лист ниже** — пройти его по каждому абзацу.
2. **Прочитать вслух** — если звучит как корпоративный пресс-релиз или как шаблонный «humanize-стиль» (рубленые фразы + числа + «я» + вопрос в конце), переписать.
3. **Фактическая сверка** — каждое число, имя, дата и история в итоговом тексте должны происходить из входных данных пользователя. Ничего выдуманного.
4. **Смысловая сверка** — факты, условия и оговорки исходника не потеряны и не искажены.

## Чек-лист качества текста

> [ ] Первые 2 предложения содержат конкретику или провокацию (если реальная конкретика доступна).
> [ ] Длины предложений варьируются (от <5 до >25 слов).
> [ ] Длины абзацев варьируются (от 1 до 6+ предложений).
> [ ] Нет списков из 3 одинаковых по грамматике пунктов.
> [ ] Нет слов-маркеров AI (см. лексические словари).
> [ ] Конкретные числа/имена/даты — где они реально известны; выдуманных — ноль.
> [ ] Первое лицо («я»/«мы») — если формат и голос позволяют.
> [ ] Есть позиция / мнение / вывод.
> [ ] Нет мета-параграфов «таким образом, мы рассмотрели…».
> [ ] Заключение не повторяет вступление.
