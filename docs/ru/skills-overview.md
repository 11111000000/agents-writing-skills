# 🛠 Обзор скилов

> Четыре продакшн-скила. У каждого свой процесс работы для AI-текста, который должен читаться по-человечески.

<br>

## 🚦 Краткая сводка

| Скил | Когда грузить | Когда **не** грузить | Версия |
|---|---|---|---|
| 🖊 **`humanize-writer`** | Написание нового текста (README, доки, блог, письмо, статус) | Комментарии в коде, JSON, короткие сообщения об ошибках | v7 (3-pass + смысловой контракт) |
| ✏ **`humanize-editor`** | Переписать готовый AI-текст | Код, математика, юридические тексты | v7 (3-pass + нулевая потеря смысла) |
| 🔍 **`anti-ai-auditor`** | Диагностика текста без правок | Когда пользователь хочет сам переписать | v7 (3-pass аудит) |
| 🩹 **`ai-pattern-rewriter`** | Правка одной фразы за раз | Переписывание целого документа | v7 (3-pass + без выдуманных фактов) |

Все четыре — на **v7**: та же 3-pass архитектура плюс смысловой контракт — переписывание не выдумывает фактов, не теряет утверждения и может вернуть уже хороший текст без изменений.

> [!warning] Смысловой контракт (v7) — редактура не выдумывает фактов
> Числа, имена, даты, причины, личный опыт и цитаты берутся **только из исходного текста**. Если утверждению не хватает факта, правка оставляет его абстрактным или помечает `[нужен факт: ...]` — она никогда не заполняет пробел правдоподобной догадкой. Потеря утверждения, выдуманный факт или снятая авторская модальность («может» → «снижает») — это **ошибка**, а не стилистический компромисс.

<br>

## 🎛 Режимы правки (proofread / light / style / deep)

Режим выбирается до начала правок. Каждый следующий режим включает полномочия предыдущего; сам режим не меняет того, что обязано сохраниться.

| Режим | Что делает | Чего **не** делает | Типичный запрос |
|---|---|---|---|
| **proofread** | Опечатки, грамматика, пунктуация, согласование | Лексику, порядок слов, структуру | «вычитай», «проверь ошибки» |
| **light** | Ясность: двусмысленности, тяжёлые конструкции, очевидный канцелярит | Ритм, голос, порядок абзацев | «поправь, чтобы читалось» |
| **style** | Ритм и естественность: длины предложений, переходы, живость | Структуру аргументации | «сделай живее», «убери AI-шность» |
| **deep** | Перестройка: порядок, объединение и разбиение абзацев, арка | Смысл; никогда не добавляет факты | «перепиши», «сделай из этого статью» |

- **RELY (айсберг-удаления) работает только в `style`/`deep`** и только для художественного или разговорного регистра — не по умолчанию, никогда для технического, делового или юридического текста.
- **Неоднозначный запрос → режим мельче.** Берите `light`, если ни текст, ни пользователь не требуют иного, и сообщайте, какой режим выбрали.
- **Хороший текст можно вернуть без изменений.** Если правка добавляет только риск — скажите «текст уже хорош» и верните исходник.
- В любом режиме глубже proofread результат проходит одну и ту же проверку сохранности смысла.

> [!info] Полная спецификация: [`editing-modes`](02-techniques/editing-modes) · [`meaning-preservation`](02-techniques/meaning-preservation)

## 📐 Архитектура: 3-проходный процесс

Все скилы делят общую структуру:

```mermaid
flowchart TB
    A["<b>PASS 1: АУДИТ</b><br/><i>идентификация</i><br/>метрики, локации, серьёзность"] --> B["<b>PASS 2: REWRITE</b><br/><i>применить 12 рычагов</i><br/>STRIP → TIGHTEN → RELY → REBUILD"]
    B --> C["<b>PASS 3: ПРОВЕРКА</b><br/><i>финальные проверки</i><br/>плотность, смысл по утверждениям, чтение вслух"]
```

## 🎯 12 рычагов в 4 фазах

| Фаза | Рычаги | Что делают |
|---|---|---|
| 🧹 **STRIP** | 1–9 | Удаляют AI-маркеры |
| 📐 **TIGHTEN** | 10 | Достаточность |
| 🧊 **RELY** | 11 | Айсберг (доверяй читателю) |
| 🇷🇺 **REBUILD** | 12 | Русская грамматика краткости (только RU) |

<details>
<summary><b>🧹 STRIP (Рычаги 1–9): убрать AI-маркеры</b></summary>

| № | Рычаг | Пример |
|---|---|---|
| 1 | **Perplexity** | `delve` → `разобраться` |
| 2 | **Burstiness** | Чередовать длины предложений (std > 5) |
| 3 | **Hedge surgery** | Удалить `можно сказать, что` |
| 4 | **Structural flatten** | Убрать раздутые буллет-списки |
| 5 | **Specificity** | `современное решение` → `p99 14ms` — только если это число есть в исходнике |
| 6 | **Voice** | Добавить «я»/«мы» только там, где это уместно регистру |
| 7 | **Discourse** | Удалить `Более того`, `Кроме того` |
| 8 | **Punctuation** | Em-dash ≤ 1 на 300 слов |
| 9 | **RLHF strip** | Удалить `Отличный вопрос!`, `Надеюсь, поможет` |

</details>

<details>
<summary><b>📐 TIGHTEN (Рычаг 10): достаточность</b></summary>

> «Не делай свой вклад информативнее, чем требуется» — Grice submaxim 2

**8 сканов** + Strunk cut-test + Williams 6 операций:

```python
TIGHTEN_SCANS = [
    "vacuum_filling",       # P-NEW-1: вводные без информации
    "restatement",          # P-NEW-2: 2+ предложения с одинаковым содержанием
    "bridging",             # P-NEW-3: "как упоминалось выше"
    "over_explanation",     # P-NEW-4: объяснение очевидного
    "anticipatory_hedging", # P-NEW-5: "возможно, в некоторых случаях"
    "balanced_framing",     # P-NEW-6: "с одной стороны, с другой"
    "antithetical_recap",   # P-NEW-7: "итак, мы рассмотрели"
    "strunk_cut_test",      # удали любое предложение, смысл выжил?
]
```

**Проверка сохранности смысла (v7) — по утверждениям, без порогов:**

```python
def check_claims_preserved(original, rewritten):
    """Проверка по каждому утверждению. Потеряно одно утверждение = FAIL. Порога «потеряли 10% — нормально» больше нет."""
    lost_facts = extract_facts(original) - extract_facts(rewritten)
    invented_facts = extract_facts(rewritten) - extract_facts(original)
    lost_claims = [c for c in extract_claims(original)
                   if not claim_survives(c, rewritten)]
    return {
        "status": "FAIL" if (lost_facts or invented_facts or lost_claims) else "PASS",
        "lost_claims": lost_claims,
        "invented_facts": list(invented_facts),   # выдуманные числа/имена = FAIL
    }
```

**Три способа провалиться — ни у одного нет допуска:**

| Провал | Пример | Статус |
|---|---|---|
| **Потеряно утверждение** | «конверсия выросла с 2% до 3%» → «конверсия составила 3%» | ❌ FAIL |
| **Выдуман факт** | «переписали кеш» → «переписали кеш, p99 упал с 800 до 90 мс» | ❌ FAIL |
| **Потеряна модальность** | «может снижать нагрузку» → «снижает нагрузку» | ❌ FAIL |

Удалять можно только явные дубликаты и пустые фразы. `extract_facts` (числа, имена, пути) остаётся дешёвым smoke-тестом — он сравнивает токены, а не смысл; вердикт выносит проверка по `meaning_map`.

> [!info] Как устроена проверка: [`meaning-preservation`](02-techniques/meaning-preservation) — построить `meaning_map` оригинала, затем сверить в обе стороны: ничего не потеряно и ничего не выдумано.

</details>

<details>
<summary><b>🧊 RELY (Рычаг 11): айсберг</b></summary>

> «Если пишущий прозу знает достаточно о том, что он пишет, он может опустить то, что знает» — Хемингуэй

**Русская традиция:** Довлатов, Шукшин, Толстой (см. [laconic-prose-models](02-techniques/laconic-prose-models)).

**Условие Хемингуэя:** underspecification работает только если автор **знает** то, что не говорит.

**Тест:** удали абзац. Читатель может продолжить мысль без него? Если да — iceberg.

**RELY работает только в `style`/`deep`** и только для художественного или разговорного регистра — не по умолчанию, никогда для технического, делового или юридического текста (см. «Режимы правки» выше). Для чужого текста, который вам отдали на правку, каждое удаление должно выдержать проверку сохранности смысла.

</details>

<details>
<summary><b>🇷🇺 REBUILD (Рычаг 12, только RU): русская грамматика краткости</b></summary>

| Приём | Что делает | Пример |
|---|---|---|
| **Парцелляция** | Расщепление | «Город стоит на реке. Отсюда — водоснабжение.» |
| **Эллипсис** | Опущение | «Я говорю по-английски, а он — по-немецки.» |
| **Литота** | Преуменьшение | «У нас пользователей — кот наплакал.» |
| **Нулевая связка** | Безличный/инфинитивный | «Пошёл в магазин. Хлеб.» |

Подробнее: [`russian-brevity-grammar`](02-techniques/russian-brevity-grammar).

</details>

## 🔍 Детали по скилам

### 🖊 `humanize-writer` — написать новый текст

**Триггеры:** «Помоги написать README» / «Набросай блог-пост про X» / «Напиши письмо Y»

```
graph LR
  A[Pre-flight:<br/>голос, лид, числа] --> B[Draft full text]
  B --> C[Audit pass]
  C --> D[Tighten pass]
  D --> E[Rupture / Trust reader]
  E --> F[Density check]
```

[Полное содержимое скила →](skills-overview) · [Исходник на GitHub](https://github.com/11111000000/agents-writing-skills/tree/main/skills/humanize-writer)

### ✏ `humanize-editor` — переписать готовое

**Триггеры:** «Сделай этот текст менее AI» / «Перепиши мой черновик» / «Гуманизируй это»

Отличается от `humanize-writer` тем, что **обязан сохранять смысл**. Добавляет:
- Проверку сохранности смысла после Tighten pass — по утверждениям, без допуска: потерянное утверждение, выдуманный факт или снятая модальность заваливают правку
- Выбор режима правки (proofread / light / style / deep)
- Выбор voice profile (casual / professional / technical / warm / blunt / laconic)

[Исходник на GitHub →](https://github.com/11111000000/agents-writing-skills/tree/main/skills/humanize-editor)

### 🔍 `anti-ai-auditor` — диагностика

**Триггеры:** «Это слишком AI?» / «Проверь этот черновик» / «Сравни две версии»

Выдаёт структурированный отчёт:
- Вердикт (Human-leaning / Mixed / AI-leaning / Strongly AI)
- Risk score 0–100
- Разбивка по метрикам (AP, D, E, YapScore)
- Риск по абзацам + конкретные места проблем
- Топ-3-5 actionable рекомендаций

[Исходник на GitHub →](https://github.com/11111000000/agents-writing-skills/tree/main/skills/anti-ai-auditor)

### 🩹 `ai-pattern-rewriter` — хирургическая правка

**Триггеры:** «Поправь только это предложение» / «Замени только 7-ю строку» / «Сделай эту фразу менее AI»

Отличается от `humanize-editor` тем, что трогает **только отмеченные spans**. Добавляет per-span проверку сохранности смысла: и потерянные, и выдуманные факты внутри span'а заваливают проверку — хирургическая правка не имеет права выдумывать число, которого хотелось.

[Исходник на GitHub →](https://github.com/11111000000/agents-writing-skills/tree/main/skills/ai-pattern-rewriter)
