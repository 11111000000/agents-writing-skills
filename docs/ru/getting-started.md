# 🚀 Установка

> Три способа. Выберите подходящий для вашего агента.

<br>

## ⚡ Вариант 1: одной фразой (рекомендуется)

Скажите агенту, на любом языке:

> **EN:** "Clone https://github.com/11111000000/agents-writing-skills and install the skills from manifest.json"
>
> **RU:** «Клонируй https://github.com/11111000000/agents-writing-skills и установи скилы из manifest.json»

Агент сделает:
1. Клонирует репозиторий
2. Прочитает `manifest.json` (каталог скилов в машиночитаемом виде)
3. Скопирует каждый `skills/<name>/SKILL.md` в свою папку скилов
4. Зарегистрирует промпты (если pi)

Никаких shell-скриптов. Никаких захардкоженных путей. Работает на любой ОС с любым агентом, поддерживающим Agent Skills.

<br>

## 🔧 Вариант 2: ручная установка

```bash
# Клонируем
git clone https://github.com/11111000000/agents-writing-skills.git
cd agents-writing-skills

# Смотрим манифест
cat manifest.json | head -30

# Устанавливаем скилы (пример для opencode)
mkdir -p ~/.config/opencode/skills
cp -r skills/humanize-writer/    ~/.config/opencode/skills/
cp -r skills/humanize-editor/    ~/.config/opencode/skills/
cp -r skills/anti-ai-auditor/    ~/.config/opencode/skills/
cp -r skills/ai-pattern-rewriter/ ~/.config/opencode/skills/

# Для pi: копируем ещё промпты
cp prompts/*.md ~/.pi/agent/prompts/
```

### Куда класть скилы по агенту

| Агент | Путь к скилам | Путь к промптам |
|---|---|---|
| **opencode** | `~/.config/opencode/skills/` | n/a |
| **pi** | `~/.pi/agent/skills/` | `~/.pi/agent/prompts/` |
| **Claude Code** | `~/.claude/skills/` | n/a |
| **Codex CLI** | per docs | вручную |
| **Другой** | смотрите документацию агента | вручную |

<br>

## 📦 Вариант 3: офлайн-установка

```bash
# 1. Установите скилы (как выше)

# 2. Установите базу знаний локально
./scripts/install-knowledge.sh
# Клонирует в ~/.cache/agents-writing-skills-knowledge

# 3. Задайте переменную окружения
export KNOWLEDGE_PATH="$HOME/.cache/agents-writing-skills-knowledge/knowledge"

# 4. Замените GitHub-ссылки в скилах на $KNOWLEDGE_PATH/ (если нужен полный офлайн)
```

> [!tip] Когда использовать офлайн
> Только если агент работает без интернета. В 99% случаев GitHub-ссылки достаточно.

<br>

## ✅ Проверка установки

### 1. Тест benchmark-skill.sh

```bash
bash scripts/benchmark-skill.sh <(echo "В современном мире важно понимать, что...")
# Должен выдать YapScore > 1.5 (из-за over-generation)
```

### 2. Спросите агента

> **EN:** "Help me write a README"
>
> **RU:** «Помоги написать README»

Агент должен сам подгрузить `humanize-writer`. Если нет, у агента нет поддержки Agent Skills, смотрите [Совместимость](skills-overview#-совместимость).

### 3. Прогоните валидаторы репозитория

Скрипты в `scripts/` проверяют, что установленная копия цела. Запускайте из корня репозитория; каждый должен завершиться с кодом `0`:

```bash
bash scripts/validate-skills.sh             # фронтматтер SKILL.md, промпты, smoke-тест бенчмарка
bash scripts/check-examples-facts.sh        # ни один блок «после» не придумывает число
bash scripts/check-knowledge-links.sh       # каждая [[вики-ссылка]] в knowledge/ ведёт в существующий файл
bash scripts/check-editing-output.sh --selftest   # валидатор смыслового контракта ловит испорченную правку
```

`check-editing-output.sh --selftest` доказывает, что валидатор действительно ловит нарушения: он скармливает ему верную правку (должна пройти) и испорченную (должна быть поймана). Сам валидатор работает по поведенческому корпусу из 24 фикстур в `tests/fixtures/editing/` (исходный текст, эталонная правка и утверждения, которые должны выжить). Остальные проверки `validate-skills.sh` прогоняет тоже (версии манифеста, устаревшие контракты, покрытие примеров, фикстуры редактуры).

## 🎛 Как ведёт себя редактор (v7)

До начала правок редактор выбирает одну из четырёх глубин. Каждый следующий режим включает полномочия предыдущего, и сам режим не меняет того, что обязано сохраниться.

| Режим | Что делает | Типичный запрос |
|---|---|---|
| **proofread** | Опечатки, грамматика, пунктуация, согласование | «вычитай», «проверь ошибки» |
| **light** | Ясность: двусмысленности, тяжёлые конструкции, канцелярит | «поправь, чтобы читалось» |
| **style** | Ритм и естественность: длины предложений, переходы | «сделай живее», «убери AI-шность» |
| **deep** | Перестройку: порядок, объединение абзацев, арка | «перепиши», «сделай из этого статью» |

- **RELY (айсберг-удаления) работает только в `style`/`deep`** и только для художественного или разговорного регистра.
- **Неоднозначный запрос даёт более мелкий режим**: `light`, если ни текст, ни пользователь не требуют иного. Агент сообщает, какой режим выбрал.
- **Смысловой контракт действует в любом режиме.** Утверждения, числа и отношения между ними, условия, исключения, отрицания, модальность, терминология, цитаты и регистр переживают правку. Потеря утверждения, выдуманный факт или снятая авторская модальность («может» → «снижает»): это ошибка, а не стилистический компромисс.
- **Недостающий факт остаётся недостающим.** Если утверждению нужны данные, которых нет в тексте, правка помечает `[нужен факт: ...]`, а не придумывает правдоподобное число.

Таблица режимов, правила фаз и правило «хороший текст не трогаем» канонически описаны в [обзоре скилов](../skills-overview#-режимы-правки-editing-modes). Полная спецификация: [`editing-modes`](../02-techniques/editing-modes) · [`meaning-preservation`](../02-techniques/meaning-preservation)

## 🎯 Первые сценарии

### Переписать AI-черновик

```bash
# В pi:
> /humanize это: [вставить AI-блог-пост]
> /audit-ai /path/to/my-draft.md
> /audit-43 /path/to/my-draft.md   # полный аудит по 43 паттернам
```

### Написать новый текст

```
> Помоги написать лендинг для новой CLI-тулы
> Набросай блог-пост про X
> Напиши письмо Y о том, почему надо сдвинуть дедлайн
```

### Диагностика

```
> Где в этом черновике звучит по-AI? [вставить текст]
> Почему мой черновик звучит так generic?
> Сравни версию A и версию B по AI-маркерам
```

Аудитор отдаёт метрики (AP, D, E, YapScore, вариативность длины предложений, конкретика) как **диагностику**: они показывают, где искать, и не выносят вердикта «AI» или «человеческий».
